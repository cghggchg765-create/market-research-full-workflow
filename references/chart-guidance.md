# 图表选型矩阵与方法规范

可视化专员（visualizer）的决策依据。**先读本文档，再决定画什么、怎么画。**

## 1. 核心原则

1. **数据驱动**：只绘制分析/收集结果中真实存在的数值；没有数据就画不出图，标"数据不足"并说明缺口，不编造数字。
2. **图表为结论服务**：每张图必须支撑报告中的一个具体结论或观察，与正文数据完全一致（数字在小数点后一位内对齐）。
3. **≥5 张图**：quick ≥5 / standard 6-8 / deep 8-12。数量按**实际内容**增减，不以图片凑数；数据充分就多画，数据贫瘠就少画并标注。
4. **每张图必备标注**：标题、单位、数据年份、来源机构。数据性质用文字说明（"据XX估算"、"据XX报告"），**图内与图注不出现 ✅/🟡/⚠️ 等符号标记**。
5. **PNG + mermaid 混合**：数据类图（柱状/折线/饼/雷达/矩阵）→ PNG（matplotlib 生成，中文用微软雅黑）；流程/时序/规划类图 → mermaid 代码块（飞书渲染为画板、本地 Typora/VSCode 可预览）。

## 2. 选型矩阵：数据形态 → 图型

| 数据形态 | 适用图型 | 典型场景 | 生成方式 |
|---------|---------|---------|:-------:|
| 时间序列（市场规模/增速/用户数逐年） | line（折线，可双轴量纲不同） | 2.2 市场规模与增速 | PNG |
| 构成占比（份额/收入构成/成本占比） | donut（环形）或 pie | 3.1 市场份额、5.2 成本结构 | PNG |
| 横向对比（竞品多维度评分） | radar（雷达） | 3.4 竞争要素矩阵 | PNG |
| 类别数值对比（价格带/客单价/频次） | bar 或 hbar（水平适合长标签） | 3.2 头部玩家、4.3 痛点频次 | PNG |
| 类别 + 多系列（分组对比） | bar（分组柱状） | 5.3 利润空间对比、经济模型 LTV/CAC | PNG |
| 多维构成累加（收入构成分层） | stacked_bar（堆叠柱状） | 5.1 商业模式收入构成 | PNG |
| 概率×影响（风险/机会评估） | heatmap（风险矩阵）或 scatter（象限图） | 6.1 风险评分卡、6.2 差异化机会 | PNG |
| 经济模型（LTV/CAC/回本周期） | bar 分组 + 阈值线说明 | 5.3 利润空间 | PNG |

| 时序规划（90天/6个月/12个月） | mermaid gantt | 7.2 分阶段计划 | mermaid |
| 用户分层/规模估算 | bar 或 stacked_bar | 4.1 用户分层 | PNG |
| 年份事件/里程碑 | mermaid timeline | 2.3 行业周期与事件 | mermaid |

## 4. specs.json 规格（PNG 部分）

visualizer 输出一个 `charts/specs.json`，`specs` 数组按报告出现顺序排列：

```json
{
  "specs": [
    {
      "id": "chart-01",                 // 编号，与报告图号一致（图1...图N）
      "type": "line",                   // bar/hbar/stacked_bar/line/pie/donut/radar/scatter/heatmap
      "title": "市场规模与增速趋势（2022-2027E）",
      "subtitle": "单位：亿元",          // 单位、口径补充
      "filename": "chart-01-market-size.png",     // 内部文件名（脚本中间态）
      "display_name": "图1 市场规模与增速趋势.png",  // 交付语义文件名
      "card_id": "K03",                 // 必须绑定知识卡片
      "source_id": "SRC-003",           // 必须绑定证据台账
      "year": 2026,
      "unit": "亿元",
      "definition": "明确指标定义和统计口径",
      "base_period": "2022-2025",
      "source": "艾瑞咨询 2026；估值",
      "notes": ["2026-2027E 为预测值"],  // 口径说明（可选）
      "figsize": [10, 6],                // 可选：覆盖默认画布尺寸 [宽, 高] 英寸（视觉检查重绘时用于缓解标签拥挤）
      "position": "2.2 市场规模与增速",  // 插入报告位置（章节标题）
      "data": { ... }                    // 按 type 见下表
    }
  ]
}
```

### 各图型 data 结构

| type | data 字段 |
|------|----------|
| bar / hbar / stacked_bar | `categories`: [标签], `series`: [{"name","values"}], values 支持数字或 "1,200" 字符串 |
| line | `x`: [年份/标签], `series`: [{"name","values"}]；双量纲系列（如金额+增速）需在 subtitle 注明 |
| pie / donut | `labels`, `values`, `center_text`(donut 可选，如 "TOP5 68%") |
| radar | `categories`, `series`（评分统一 0-10 或同量纲） |
| scatter | `points`: [{"x","y","label"}], `xlabel`, `ylabel`, `quadrants` 可选（象限图：{"x":0.5,"y":0.5,"q1":"领先","q2":"...","q3":"...","q4":"..."}） |
| heatmap | `rows`, `cols`, `matrix`: [[...]], `color_scale`: "risk"(红黄绿)|默认 YlOrRd, `colorbar_label` |

### 图题三层规范（案例范式：标题/subtitle/来源）

每张图三层标注，**subtitle 承载"一句话主结论"**（案例：图1 subtitle「生成式AI投资CAGR超49%，2031年整体市场有望突破450亿元」）：

- `title`：图表名称 + 时间范围（如「财税SaaS市场规模与增速（2022-2027E）」）——**单位不入 title**，放入 subtitle 或轴标签
- `subtitle`：一句话主结论（可含单位口径），如「CAGR 约 25%，2027E 市场有望突破 870 亿元（单位：亿元）」
- `source`：`{来源机构}、{来源机构}，本研究整理` 或 `本研究测算`（与正文表格"资料来源"同构）

### 系列与标签命名（案例范式）

- 系列名 = 指标 + 单位：`'市场规模（亿元）'`、`'同比增速（%）'`
- 场景/阵营名 = 业务域或阵营标签，长度 ≤12 字（过长会触发布局 WARN）
- 数据点标签直接上标（不依赖 hover 也能读数）；长分类名用 `\n` 换行或缩短

### 选型口诀补充（案例）

- 量级跨度大（跨 2-3 个数量级）→ 横向条 + 对数轴（工具暂不支持对数轴 → 用分段/注释替代并说明）
- 占比 + 多维禀赋 → 饼 + 雷达双拼（各占一张图，位置相邻）
- 结构演变（占比随时间迁移）→ 堆叠柱
- 架构分层关系 → mermaid 流程图（替代案例的 HTML 卡片）
- 情景推演 → 多系列折线（乐观/中性/悲观）
- 二维评估 → 散点矩阵（象限线）

**生成命令**（编排者执行，CWD=skill 根目录）：
```
./.venv/Scripts/python.exe scripts/charts/gen_chart.py --spec charts/specs.json --outdir {交付目录}/charts
```
支持 `--dpi`（默认 150）。脚本输出每张图的文件名/标题/字节数，全部成功退出码 0；任一图失败会打印完整堆栈并退出非 0——此时修改 specs.json 后重新执行，**不要手工 PS 图片**。

## 5. mermaid 部分规范

mermaid 条目也放进 specs.json（type: "mermaid"），编排者在 Step 3c 把它的 `code` 作为 mermaid 代码块嵌入报告：

```json
{
  "id": "chart-07",
  "type": "mermaid",
  "title": "产业链与价值分布",
  "code": "flowchart LR\n  A[上游...] --> B[中游...]",
  "lang": "flowchart",        // flowchart / gantt / timeline / pie(勿用，数据图走PNG)
  "position": "2.1 定义与产业链"
}
```

语法要求：
- flowchart：节点用中文，箭头语义准确，控制节点数 ≤12
- gantt：`dateFormat YYYY-MM`，里程碑用 `milestone`；阶段 90天/6个月/12个月
- **禁止** mermaid pie（中文字体在部分渲染器乱码，构成类一律 PNG 环形图）

## 6. 自检清单（visualizer 交付前逐项过）

- [ ] 总数满足档位配额（quick ≥5 / standard 6-8 / deep 8-12）
- [ ] 图号连续（图1~图N），与 specs.json `id` 编号一致
- [ ] 每张图有标题/单位（如适用）/数据年份/来源
- [ ] 数据与分析结果一致（抽查 3 个关键数字）——不一致立即修正
- [ ] 估算数据在 source 或 notes 中标注"估算"
- [ ] 数据不足的条目不入 specs.json，单独列出"图表缺口"说明
- [ ] 不重复表达同一数据（同一数字只画一张图）
- [ ] PNG 文件名语义化（chart-01-market-size.png），不带空格/特殊字符

## 7. 禁止项

- 无数据硬画（宁缺勿滥，标"数据不足"）
- 编造/臆测数值，或把"估算"写成"实际"
- 坐标轴截断夸大差异、饼图比例失真这类误导性画法
- 同一张图塞 >5 个系列（可读性崩塌）
- 用 emoji 当数据标签、中文乱码不做修复直接交付
- 图内或图注出现 ✅/🟡/⚠️/❌ 等符号标记（数据性质一律用文字说明）
